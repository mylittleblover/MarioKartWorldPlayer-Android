## 一、你在接什么

**Mario Kart World 音乐播放器（Android）**，包名 `com.mylittleblover.mkwplayer`。

## 三、本轮已完成（已验证）

### 3.1 Opus（codec kind 2）解码 —— 最大的一项

MKW 有两类 BWAV：kind 1 = DSP-ADPCM（赛道），kind 2 = 分块 Opus（Jukebox 227 个 + 部分过场）。

**修复前**：227 个 Jukebox 文件全部无法播放。

**两个真实缺陷**：

1. `engine/native/decoder/BwavFormat.hpp` 的 `parseBwavOpusChannel` 里，pre-skip 读的是 `start+8+16`，实际在 `start+8+20`。错一个字，**227 个文件在解析阶段全部被拒**，从未进解码器。
2. `BwavSource.cpp` 里 `if(opusChannels.size()!=1) fail(UnsupportedChannels)`。注释说「多流是 CG 和音效」——**事实是 Jukebox 全是 2 条流**。每条流是独立的 **mono** Opus，不是立体声流的一个声道。用立体声解码器解 mono 包会每个包都失败。

**解法**：新增 `MultiOpusSource`（`OpusSource.cpp`），每条流独立 mono 解码器，按包链解码后交错成 2 声道。`render` 按包循环推进，`seek` 重新开解码器再解码丢弃。

**验证**：写了真机探针 `tools/interactive-preview/bwav_decode_probe.cpp`，走与 App 完全相同的 `openBwav()`。**227/227 解码成功，0 拒绝，0 静音**，含 seek 与双声道独立性检查。

### 3.7 循环接缝研究

`docs/research/2026-11-15-bwav-loop-seams.md`，六个可重跑脚本在 `tools/`。

**核心结论（与常见假设相反）**：

- 20 991 个 BWAV 中 2 881 个带循环元数据，其中 174 个是 BGM。
- **174/174 的 `frames == loop_end`** —— 循环点之后一个采样都没有，物理上不存在「循环终点后的衔接段」。
- 循环终点前的相似度只有 4/174 过 0.80，且全是 5–15 ms 的对齐窗口，不是可剪的音乐段。
- **BWAV 循环窗口 == MINF 循环窗口，106/106 逐帧一致。**

**所以「按拍点削掉循环衔接段」在这份数据上不可行** —— 游戏数据本身就是那个点，没有余量可削。要做按拍切换，只能在播放侧用 MINF 拍线（引擎的 `NextBar` / `NextBeat` 同步点）。

## 四、未完成 / 已知缺陷

按严重程度排：

### 4.1 【严重】Jukebox 曲目在 App 内仍无法播放

```
Cannot play this flow
Could not bind 'MAIN_0_<hash>.bwav': The engine rejected the request.
```

**同一条 `openBwav()` 在探针里 227/227 成功**，所以解码器没问题，问题在引擎绑定链路：

```
VolumeTable/PackPlayback.prepare
  → PlayerViewModel.startFlow
  → PlaybackSession.loadFlow
  → AudioEngine.bindBwav  (PlaybackSession 调 current.bindStreamedBwav 或 bindBwav)
  → JNI prepareSource
  → api::bindEngineSource
  → openAudioSource → openBwav           ← 探针证明这步 OK
  → runtime->bindAsset(buffer)
     ↑ 这里有三项相等检查，任一不符就 InvalidRequest：
       buffer->sampleRate == asset->sampleRate
       buffer->channels   == asset->channels
       buffer->frames()   == asset->frames
```

`EngineRuntime::bindAsset`（`EngineRuntime.cpp:32-42`）是最后一道，三项任一不符就返回 `InvalidRequest`，App 把它显示成泛化的 "The engine rejected the request"。

**下一步应该做什么（明确建议）**：
写一个探针，走 `loadCompiledGraph` + `prepare` + `runtime->bindAsset`，把 `asset->sampleRate/channels/frames` 与 `buffer->sampleRate/channels/frames` 分别打印出来对比。**不要继续猜** —— 我在这一点上已经耗掉了一轮上下文。

怀疑方向（均未验证）：
- `GraphBuilder` 写入的 asset `frames` 与 `BwavHeader` 解析出的 frames 不一致（Jukebox 是 codec 2，`BwavHeader` 用 `+12` 的 frame 数，而 Opus 的 duration 是 `packets × 960 − preSkip`，两者可能不等）。
- **这一条最可疑**：`parseBwavOpusChannel` 里 `layout.metadata.duration = samples`（容器声明值），但图里写的可能是别的。
- `channels`：multi-Opus 源现在报 2 声道，而 graph 里若写的是 1 就失败。

### 原生探针（唯一能在无宿主编译器的机器上跑原生代码的方式）

```powershell
$cm = "$env:ANDROID_HOME\cmake\3.22.1\bin\cmake.exe"
$ninja = "$env:ANDROID_HOME\cmake\3.22.1\bin\ninja.exe"
$ndk = "$env:ANDROID_HOME\ndk\27.0.12077973"

& $cm -S "$w\tools\interactive-preview" -B "..\_hostbuild-x64" -G Ninja `
  -DCMAKE_MAKE_PROGRAM="$ninja" `
  -DCMAKE_TOOLCHAIN_FILE="$ndk\build\cmake\android.toolchain.cmake" `
  -DANDROID_ABI=x86_64 -DANDROID_PLATFORM=android-26 -DANDROID_STL=c++_shared `
  -DCMAKE_BUILD_TYPE=Release
& $cm --build "..\_hostbuild-x64" --target mkw_bwav_decode_probe -j 8
```

**必须注意**：

- **ABI 要选 `x86_64`** —— 模拟器是 x86_64，默认 arm64 的产物装上去报 "not executable: 64-bit ELF file"。
- **必须 `-DANDROID_STL=c++_shared`**，并把 `libc++_shared.so` 推到 `/data/local/tmp`，运行时 `LD_LIBRARY_PATH=/data/local/tmp`。
- 同理 `libgme.so` 也要推。
- push 完要 `chmod 755`。

## 七、硬规则（踩过雷，别重复）

1. **不要发明内容。** 没有封面就不给封面，没有目录就显示空态。地图裁切不是赛道风景；邻近赛道的图不是这个赛道的图。
2. **方向不能补。** 连接表 22 条单向边是真的单向。彩虹之路只有 1 条入边。
3. **计数只在测量之后说。** `frames` 之和不是真实时间轴；「N 条连接」要说明是表里的还是画出来的。
4. **翻译文字不进身份。** 声源摘要、图节点、导航键、收藏 id 都用稳定 id，不用显示名。
5. **UI 计时不改原生钟。** 进度条 220 ms 插值只影响显示。
6. **设置项改了要能生效。** 增益、语言这类，改完必须下发到正在运行的引擎，不能只存不推。
7. **状态描述要指向同一个子系统。** 「播放中」不能是 UI 动画状态，「无法播放」要说出具体哪一步失败。
8. **没听过的不要说听过了。** 模拟器无音频，任何音质/无缝循环的结论都必须标「未听感验证」。

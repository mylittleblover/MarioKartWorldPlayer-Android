# BWAV 循环接缝测量（2026-11-15）

对 MKW 原始 BWAV 的循环窗口做一次实测：**循环终点附近是否预留了一段与循环起点相似的音频**。有些文件有，有些没有——这个不对称本身是结论，不是测量失败。

所有数字来自本机脚本对真实文件的运行，没有推断值。可复现的脚本列在文末。

## 二、两个可能的位置，分别实测

"预留接缝"有两种可能的实现，都必须测，因为结论不同：

### 位置 A：循环终点**之后**

若导出器在 `loop_end` 之后还留了数据，引擎就能越过循环点去取。

**实测：174 个文件的 `frames == loop_end`，全部相等。**

```
frames == loop_end（无尾部）      : 174
frames  > loop_end（有尾部）      : 0
frames  < loop_end（循环点超界）  : 0
```

**结论：这块数据里，循环终点之后一个采样都没有。**位置 A 不存在。

### 位置 B：循环终点**之前**

这是唯一可能的位置。方法：在 `loop_end` 前取 lag 帧，与 `loop_start` 起的 lag 帧做去均值归一化互相关，lag 从 5 ms 扫到 2 s。

| 阈值 | 值 | 理由 |
|---|---|---|
| 相关系数下限 | **0.80** | 远高于同长度无关音乐偶然能达到的水平 |
| 最短接缝 | **240 帧（5 ms）** | 短于此与导出对齐误差无法区分 |

结果：

| 项 | 数量 |
|---|---|
| 有接缝（corr ≥ 0.80 且 lag ≥ 240） | **4** |
| 无接缝 | **170** |

4 个有接缝的文件：

| 文件 | corr | 接缝长度 | 时长 |
|---|---|---|---|
| `BGM_Stage_MooMooFarm_Pre_Short` | 0.872 | 264 帧 | 5.5 ms |
| `BGM_Stage_Central_Pre_Short` | 0.863 | 240 帧 | 5.0 ms |
| `BGM_Stage_MooMooFarm_Pre` | 0.858 | 264 帧 | 5.5 ms |
| `BGM_Battle_02_FL` | 0.820 | 744 帧 | 15.5 ms |

**这 4 个的"接缝"全是 5–15 ms 量级。**这不是一小节、也不是半拍——它是编码器/导出器的**几毫秒对齐窗口**，不是一段可剪辑的音乐素材。

相关性分布（174 个文件）：

| 分位 | corr |
|---|---|
| p50 | 0.334 |
| p90 | 0.659 |
| p95 | 0.726 |
| p99 | 0.863 |
| max | 0.872 |

分布是**连续单峰**，不是双峰：最大间隙在 0.7661 → 0.8202（0.054），仅此一处略宽。也就是说没有"一群有接缝、一群没有"的自然分界，0.80 这条线是人为选的，且只有 4 个文件越过它。

## 三、另一件事：循环**起点之前**有没有预留

这是"预留接缝"的另一种可能读法——在 `loop_start` 之前留一小段，让第一次回环能淡入头部。

方法：比较 `[loop_start - lag, loop_start)` 与 `[loop_start, loop_start + lag)`。

| lag | 时长 | 全库中位相关系数 |
|---|---|---|
| 240 | 5 ms | **−0.013** |
| 480 | 10 ms | 0.021 |
| 960 | 20 ms | −0.003 |
| 1 920 | 40 ms | 0.011 |
| 4 800 | 100 ms | 0.012 |
| 9 600 | 200 ms | 0.003 |
| 24 000 | 500 ms | 0.001 |

**中位数全部接近 0。**也就是说，循环点之前的音频与循环头**没有**系统性相似——它是正常的前置音乐，不是预留的衔接段。

只有 6 个文件超过 0.80：

| 文件 | lag | corr |
|---|---|---|
| `BGM_Stage_Cave_Pre_Short` | 480（10 ms） | 0.929 |
| `BGM_Stage_WarioStadium_Pre_Short` | 480（10 ms） | 0.911 |
| `BGM_Stage_WarioStadium_Pre` | 480（10 ms） | 0.901 |
| `BGM_Stage_MooMooFarm_Pre_Short` | 240（5 ms） | 0.851 |
| `BGM_Stage_MooMooFarm_Pre` | 240（5 ms） | 0.836 |
| `BGM_Stage_LagoonCity_Pre` | 240（5 ms） | 0.818 |

**同样都是 5–10 ms 量级。**这更像是某个乐器在这两个位置恰好是同相位（例如持续低音），而不是设计出来的衔接段。

## 四、与游戏自己的拍点对齐

MINF 数据里有每个资源的 BPM 与逐拍帧位置。把 174 个循环 BGM 文件与之连接：

| 项 | 结果 |
|---|---|
| 能连上 MINF 记录 | **106 / 174** |
| 连不上（Battle / Demo / Mission 等无 MINF） | 68 |
| **BWAV 循环窗口 == MINF 循环窗口** | **106 / 106** |
| 循环起点正好落在拍线上 | 54 / 106 |
| 循环终点正好落在拍线上 | 55 / 106 |
| \|起点 − 最近拍\| 中位 / 最大 | 0 / 6 625 帧 |
| \|终点 − 最近拍\| 中位 / 最大 | 0 / 6 626 帧 |
| 循环长度（拍）最小/中位/最大 | 8.00 / 116.00 / 236.01 |

**关键结论：BWAV 头里的循环窗口与 MINF 记录的循环窗口 106 个全部逐帧相同。**两者不是各自独立的两个来源，是同一个事实的两次表述。

约一半文件的循环点精确落在拍线上，另一半偏离；偏离的也不一定是"错"——6 625 帧约 138 ms，在 154 BPM 下约 0.35 拍，属于半拍/切分位置。

3 个有接缝的文件同时能连上 MINF，接缝长度**都在一拍之内**（240–264 帧 vs 一拍 18 000–22 500 帧），即接缝远小于一拍，不可能落在"下一拍"上。

## 五、结论

**用户观察到的不对称是真实的，但成因不是"预留了循环衔接段"：**

1. **循环点之后没有任何音频**（174/174 全部 `frames == loop_end`）。所谓"循环终点的衔接部分"在物理上不存在——引擎无数据可取。
2. **循环终点之前的相似度只有 4/174 个文件过线，且全部 ≤ 15.5 ms。**这是毫秒级对齐窗口，不是可剪掉的音乐段落。想"按拍数的点去掉衔接部分"，没有东西可去。
3. **循环起点之前的中位相似度接近 0**，说明那里是正常前置音乐，不是预留的淡入段。
4. **BWAV 循环窗口 = MINF 循环窗口（106/106 逐帧一致）**，所以"按游戏数据的拍数取点"这件事，**游戏数据已经就是那个点**——循环点本身就是它。

**因此：无法从这份数据里得出"某些文件预留了循环衔接段、可以按拍点削掉"的结论。**能得出的是相反的事实：这些循环是硬切在 `loop_end` 上的，引擎要平滑只能在播放侧做交叉淡化，源文件里没有可供剪掉的余量。

若要做"按拍点切换"，可行的做法是**在播放侧按 MINF 拍线选切换时刻**（引擎现有的 NextBar / NextBeat 同步点就是这个机制），而不是去修剪音频。

---

## 六、限制

- 只测了 `BGM_*` 前缀的 174 个文件。其余 2 707 个循环文件是音效/界面/环境声，其循环是机械性的，未测。
- 相关系数是**单声道下混**上算的。这两个声道是同一次导出的一半，接缝属编辑属性而非单个扬声器属性，故下混合理；但没有分别验证左右声道是否给出不同答案。
- 68 个文件无 MINF 记录（Battle / Demo / Mission / 部分 Rainbow），其循环点无法与拍线比对。
- 0.80 这个阈值是**选的，不是推导出来的**。分布是连续单峰、无自然分界，所以"有接缝的文件数"随阈值变化：0.75 时是 6 个，0.90 时是 0 个。
- 未做听感验证。没有真机音频输出，全部结论基于信号相关与头部字段。

## 七、如何复现

脚本均在 `tools/`：

| 脚本 | 作用 | 输出 |
|---|---|---|
| `scan_bwav_loops.py` | 扫全部 20 991 个 BWAV 的循环头 | `reports/generated/bwav-loop-headers.json` |
| `inspect_loop_windows.py` | 统计 pre-roll / tail / 循环长度 | 控制台 |
| `inspect_loop_tails.py` | 尾部与相关性分布形状 | 控制台 |
| `analyse_loop_seams.py` | 循环终点前的接缝扫描（位置 B） | `reports/generated/bwav-loop-seams.json` |
| `analyse_preroll_similarity.py` | 循环起点前的相似度（另一种读法） | `reports/generated/bwav-preroll.json` |
| `join_loop_beats.py` | 连接 MINF 拍线 | `reports/generated/bwav-loop-beats.json` |

运行方式：

```powershell
$py = (Get-Command python -ErrorAction Stop).Source
& $py -X utf8 tools\scan_bwav_loops.py          # ~128 s
& $py -X utf8 tools\inspect_loop_windows.py
& $py -X utf8 tools\inspect_loop_tails.py
& $py -X utf8 tools\analyse_loop_seams.py       # ~6 min
& $py -X utf8 tools\analyse_preroll_similarity.py
& $py -X utf8 tools\join_loop_beats.py
```

依赖：Python 3 + numpy（本机 runtime 已带）。不需要 scipy。

## 2. 不能做的事（必须说清）

| 限制 | 影响 |
|---|---|
| **没有人耳听过** | 所有"能播放"的结论都基于 PCM 数值，不是听感 |
| **kind=2 编码不支持** | 253 个音乐文件（含 **227 首 JukeBox**）无法播放 |
| **无真实曲库 UI** | 当前界面只能自检，不能选曲播放 |
| **标记名→Outro 绑定未确认** | 两份分析产物矛盾 127/165，不能写进产品 |
| **未在真机（ARM）上跑过** | 仅 x86_64 模拟器 |

## 3. 本轮修掉的真实缺陷

| 缺陷 | 影响面 | 发现方式 |
|---|---|---|
| BWAV 末块截断未处理 | **5,694** 个文件被拒 | 全库实测 |
| 预测器种子校验过严 | **654** 个文件被拒 | 全库实测 |
| CRLF 破坏 pinned SHA256 | 构建失败 | 构建报错 |
| `gme_shared` 链接语言错误 | 构建失败 | 链接错误 |
| JNI 包名与 Kotlin 不匹配 | 运行时崩溃 | 契约测试 |
| `loadLinear` 丢弃已加载的图 | 测试假阴性 | 诊断分路径 |
| 有图时 `Play(-1)` 返回 Ok 但静音 | 测试假阳性 | 断言音频而非状态码 |

**前两条是本轮最有价值的发现** —— 它们让"能播放真实游戏音频"这件事从不可能变成可能。

## 6. 下一步（按价值排序）

1. **真实曲库 UI + 文件选择器** —— 让用户能实际选曲播放。这是从"技术验证"到"能用"的关键一步。
2. **kind=2 编码攻克** —— 需要外部线索（文档或已知正确的解码器），否则 227 首 JukeBox 永远不可用。
3. **真机验证** —— 模拟器能证明的到此为止；真机能验证性能、热切换、真实听感。
4. **标记名绑定确认** —— 需要 L3 证据（游戏内实测）。

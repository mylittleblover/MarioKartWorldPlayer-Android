# AND-39 · BWAV codec 2 解码（已解）

- **checked_at**: 2026-11-08T18:30+08:00 (Asia/Shanghai)
- **结论**: **格式已确定并已验证** —— codec 2 是**裸 Opus 包**，容器为
  `[u32 BE size][4 字节未知][Opus packet]`，每包 960 采样 / 20 ms / 单声道。
  与 vgmstream 逐采样比对，**594/594 声道全部吻合（最大差 1 LSB）**。
- **推翻了** `and-07` / `and-17` 的 `DECODE_UNRESOLVED` 结论

---

## 1. 这轮推翻了什么

上一轮的两个"已排除"是**方法错误**，不是格式性质：

| 旧结论 | 为什么错 |
|---|---|
| 「全库搜不到 Ogg / OpusHead magic」 | 本来就是**裸包**，没有 Ogg 封装，当然没有 magic。把「没有封装」读成了「不是 Opus」 |
| 「48 种变长包链组合全部 0 匹配」 | 那 48 种都是 `长度前缀` **紧接** `载荷`。真实布局在两者之间**多 4 个字节**，所以每一种都在第 2 包就错位。`k2_framing.py` 的 width 只试了 1/2/3/4，没有试过 8 字节头+4 字节空隙 |

**教训**：旧脚本把「长度前缀」和「载荷」当成紧邻。真实布局在两者之间多 4 个字节，
所以每一种组合都在第 2 个包就错位，而错位后仍然"能读出一些数"，看上去像"没有精确匹配"
而不是"假设缺了一项"。真正定位靠的是包长中位数 201 加上 8 字节头 = 209，
与 `and-17` 记录的 0.2177 字节/采样对上——**算术对上了，格式才对上**。

## 2. 已确认的格式（594/594 声道，零例外）

### 2.1 容器

每个 kind-2 声道区域仍是 `and-17` 记录的两个 chunk：

```
u32 tag 0x80000001, u32 size 24, {256, 48000, 32, 0, 0, 120}
u32 tag 0x80000004, u32 size N, payload[N]
```

配置块全库**完全一致**，594/594。

### 2.2 包链（这是本轮的关键发现）

payload 是**连续的包**，每包一个 8 字节头：

```
u32 packet_size   (big-endian!)      ← 注意是 BE，容器其余部分都是 LE
u8  opaque[4]                        ← 含义未知，解码不需要
u8  packet[packet_size]              ← 一个完整的 Opus 包
```

**594/594 声道恰好消费完 payload，余数 0，零失败。**
全库 3,993,052 个包，834,558,601 字节。

一个反例足以说明这不是巧合：`BGM_JukeBox_M001B_...` ch0 是 1,611,390 字节、7,710 个包，
`7710 × 8 + Σsize = 1611390`，精确到字节。

### 2.3 每个包都是 Opus，且参数恒定

**全部 3,993,052 个包的首字节都是 `0xF8`，无例外。**

按 RFC 6716 §3.1 拆 TOC：

```
0xF8 = 11111 0 00
       config=31  s=0  c=0
```

- `config 31` → CELT fullband
- `s=0` → 单声道（每个声道区域独立编码，不是立体声对）
- `c=0` → 一个帧，帧长由 config 31 决定 = **20 ms = 960 采样 @ 48 kHz**

包长 101–401 字节，均值 **201.003**，中位数 201，其中 53.78% 恰好是 201 字节。
201 字节 / 960 采样 / 20 ms = **83.6 kbps** —— 与 `and-17` 记录的
0.2177 字节/采样、83.6 kbps 完全一致。这个"恒定码率"就是 CBR 目标码率的签名，
而它**恰好等于** `(201 + 8) 字节 / 960 采样`。

### 2.4 采样数对账

| 量 | 值 |
|---|---|
| 每包采样 | 960 |
| `960 × 包数 − 声明采样数` | 1 … 960，均值 516.31 |
| 需要丢弃的起始采样 | **120** |
| 包不够补满的声道 | **38 / 594**（缺口 20–119 采样） |

`960 × 包数 − 120 = 声明采样数` 对 556/594 声道精确成立；剩下 38 个声道
`960 × 包数 − 120` **小于**声明采样数，即包本身不够长。

**这 38 个声道的尾部，vgmstream 输出的是纯静音**（已逐个测过：超出可用范围的
参考采样全部为 0）。所以「补静音到声明长度」不是猜测，是实测行为。

**120 这个数不是凭空来的**：它就是配置块的第六个字。
配置块 `(256, 48000, 32, 0, 0, 120)` 的最后一个字段 = 120 = 需要丢弃的起始采样数。

这不是巧合：**CELT-only 模式的解码器延迟正好是 2.5 ms**，48 kHz 下就是 120 采样；
而 2.3 已经独立测出 config 31 = CELT fullband。两个独立测量指向同一个数。

配置块这六个字里，`48000`（采样率）和 `120`（pre-skip）可以认为解释清楚了。

## 3. 验证（这是本轮的核心，不是"听起来像"）

### 3.1 方法

用 Python 按 2.2 的规则切包 → 装进最小 Ogg Opus 容器（只为喂解码器）→
用 **FFmpeg 自带的原生 Opus 解码器**解码 → 与 **vgmstream** 解码同一文件的结果逐采样比对。

两个解码器互相独立：FFmpeg 用的是它自己的 Opus 实现（日志里写作 `opus (native)`），
vgmstream 链接的是 Xiph libopus。两套独立实现给出同样的 PCM，只能说明
**包切分是对的**、包**确实是 Opus**，而不是"某个解码器被我们骗着出了声"。

### 3.2 结果

全库 **594/594 声道**：

| 指标 | 值 |
|---|---|
| 最大绝对差 | **1 LSB** |
| RMS 差 | 0.005 – 0.011 LSB |
| 差值 > 1 LSB 的声道 | **0** |
| 对齐偏移 | 恒定 120 采样 |

1 LSB 的差异来自两个解码器浮点→整型的舍入，不是格式差异。举例
`BGM_Demo_Staffroll.bwav`（15,498,140 采样）：15,498,120 个可比采样里有 1,691 个差 1，
最大差 1。

**这就是"已验证"的判据**：不是"出声了"，是"和参考解码器逐采样一致"。
一个只保证"听起来像音乐"的实现通不过这一关——采样级偏差会在频谱上表现为宽带噪声叠加，
而参考比对会直接显示最大差远大于 1。

## 4. 仍然不知道的（精确到字节）

### 4.1 每包 4 字节未知字段

`[u32 size]` 后面那 4 个字节，含义**未确定**。

已排除（各测 2,686–170,650 个包，命中 0）：

| 假设 | 结果 |
|---|---|
| crc32-ieee / bzip2 / mpeg2 / posix / crc32c / adler32（BE 和 LE） | 0 |
| 包长的某种变体 | 0 |
| 累计采样位置 / 单调计数器 | 否（与索引相关系数 0.0001） |

已知的性质：3,993,052 个值里 2,226,901 个互不相同；首字节非零者 3,494,011。

**这 4 个字节不影响解码**——上面的验证是在完全忽略它们的前提下做的，
594/594 声道仍然逐采样吻合。它可能是校验、可能是编码器内部状态，
不影响"能正确解码"这个结论。

### 4.2 配置块其余字段

`256`、`32`、`0`、`0` 的含义仍未确定。只有 `48000`（采样率）和 `120`（pre-skip）
对上了。`256` **不是**帧长——帧长是 960。

**但这一条不影响任何结论**：解码路径只用到 48000 和 120，其余四个字既不参与
切包也不参与解码，改天弄清楚了也不会改变输出。

## 5. 上一轮"固定帧"假说为什么失败

值得记下来，因为它是**看起来最像**的错路：

- 209 字节 ≈ 960 采样，`payload_size` 对 209 取模，427/594 恰好整除
- 于是"209 字节固定帧"看起来成立

**它是平均值造成的假象。** 真实包长在 101–401 之间变化，均值 201.003；
加上 8 字节头 = 209.003。所以"209 的整数倍"只在那些恰好整除的声道上成立，
其余 167 个声道的余数（0–200，分布很散）正是「均值 209 但不是定长」的证据。
用 `d = payload − 209·ceil(samples/960)` 能看出 381 个 d=0、46 个 d=209、其余散落
——这个残差结构本身就是"可变长包 + 均值 209"的指纹，当时被读成了"接近但不精确"。

## 6. 落地所需的完整规格

```
每声道：
  payload = 音频 chunk
  p = 0
  while p + 8 <= len(payload):
      size = BE_u32(payload[p : p+4])
      packet = payload[p+8 : p+8+size]
      decode(packet) -> 960 个 int16 采样（单声道，48 kHz）
      p += 8 + size

  解码后：
      丢弃前 120 个采样
      输出直到累计 声明采样数 个采样
      不足则补 0
```

不需要 Ogg 封装、不需要 OpusHead、不需要 seek 表——容器已经把包边界给全了。
`opus_decode()` 每次调用给 960 采样，`opus_packet_get_nb_samples()` 可用于校验。

## 7. 生产解码器的选择：framing + 现有 libopus，**不要**引入 vgmstream

| 方案 | 成本 | 判断 |
|---|---|---|
| **framing + `third_party/opus`** | 一个解析器（约 100 行）+ 已有 `Opus::opus` 目标 | **推荐** |
| 引入 `libvgmstream` | 数十万行、C89、Windows 版自带 FFmpeg、ISC + 一堆第三方 | 拒绝 |

理由：

1. **依赖已经在仓库里。** `engine/native/CMakeLists.txt:45-47` 已经 `add_subdirectory(third_party/opus)` 并
   `target_link_libraries(player2_engine PRIVATE Opus::opus)`，`decoder/OpusSource.cpp` 已经在用。
   codec 2 只需要在 `BwavFormat.hpp` 里多一个分支，把包喂给同一个 `opus_decode`。
2. **vgmstream 的 Opus 路径在 Windows 版里就是靠 libopus**，而它的 Android 构建要额外拖 FFmpeg
   或自己裁剪——为了 253 个文件引入整套 vgmstream 不划算。
3. **许可证**：vgmstream 是 ISC（宽松），引入本身不违规，但 `NOTICE-THIRD-PARTY.md`
   要新增一条，且 `third_party/` 的 SHA256 固定约定要求整棵树入库。收益远小于成本。
4. **vgmstream 保留为验证工具**，不进产物。它的价值是**参考**，不是运行时。

`BwavFormat.hpp` 现在 `if(kind>1)fail(SourceStatus::UnsupportedCodec);`（第 29 行），
这就是唯一需要改的地方。

## 8. 前 120 个采样确实是解码器预热，不是音乐

这一点单独测过，因为它决定了 `preSkip=120` 是不是在切掉音频：

| 范围 | 绝对峰值 |
|---|---|
| 采样 0–119（被丢弃） | **133** |
| 采样 120–239 | 515 |
| 整段 | 4456 |

前 120 个采样从 `0, 0, 0, 0, 0, 1, -1, 0, ...` 开始爬升——这正是 CELT 解码器
从零状态起步的重建过程。峰值只有整段的 3%，且开头五个采样全是 0。
**丢弃它是对的；保留它会在每首歌开头留一段 2.5 ms 的淡入伪影。**

## 9. 落地到代码时的已知坑（供下一个改动的人）

`engine/native/decoder/OpusSource.cpp` 已经是一个可复用的包驱动 Opus 源，`OpusLayout`
里 `packets[i].frames` 会在 `prepare()` 里和 `opus_decode_float()` 的返回值严格比对
（第 35 行 `if(count!=packet.frames)fail(...)`）。所以接入 codec 2 时：

1. **`frames` 必须填 960**，不是 `opus_packet_get_nb_samples()` 的返回值之外的东西——
   实测两者一致，但严格比对意味着先算错就会整个源变成 `MalformedSource`。
2. **`preSkip` 填 120**（配置块第六字），`OpusSource` 会自己从 `preSkip` 开始取。
3. **最后一个包可能不够**：38 个声道的包总长 `960×包数−120` 小于声明采样数，
   而 `OpusSource::render()` 从 `preSkip` 起按 `min(wanted, end-raw)` 取，
   取不满的部分由第 62 行补 0。**这个行为是对的**，不要"修复"它。
4. `preSkip` 是 `unsigned`，`position_` 是 `int64`，第 54 行的加法没有溢出问题
   （最长声道 17,856,102 采样）。

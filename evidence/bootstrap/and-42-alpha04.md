## 1. 你要求的演出流程，现在按你说的实现了

```
前奏  循环，无限，直到收到事件
  |   advance()          ← 比赛开始
  v
Main  循环；通过过渡规则进入，规则里带 Bridge 就先播 Bridge
  |   takeOutro(位置)    ← 圈结束
  v
Outro  按当前进度选最近的；不循环
  |
  v
结束
```

### 上一次为什么「播了前奏就停」

**不是驱动器的 bug，是引擎的事实**：引擎靠「段变为 inactive」结束一段，**并且它不会自己跟着过渡走**。

而我之前等的是「前奏播完」——**它永远不会播完**，因为前奏现在循环。

### 所以现在每一次推进都是命令

| 控制 | 类型 | 何时可用 |
|---|---|---|
| **Start** | 命令 | 未在演出时 |
| **Next stage** | **事件** | **仅前奏循环时** |
| **Fast version** | 开关 | Main 循环时 |
| **End the stage** | **事件** | Main 循环时 |
| **Stop** | 命令 | 演出中 |

**每个按钮只在有意义时可点** —— 永远可点的按钮就是有时点了没反应的按钮，而听众分不出来。

## 2. 除 Outro 外所有段落都循环

**包括没有测量 loop 窗口的段落。**

前奏如果跑到底就停，引擎就没东西在播了 —— **这正是上次停住的原因**。

Outro 不循环：它是最后听到的东西，循环它演出就永远结束不了。

## 3. Fast 版本：真角色 + 双向交叉淡化

| 事实 | 值 |
|---|---|
| 带 `_Fast` 的文件 | **61 个** |
| 带 `Pattern` 的文件 | 8 个 |

**Fast 和 Main 是同一首曲子的不同速度**，所以切换**必须是交叉淡化**：

- 编译成**双向**过渡规则（Main→Fast、Fast→Main）
- **在小节线上**切换 —— 乐句中间切换，即使有淡化也像出错
- 淡化时长在 `Timing.fastFadeBeats` 里，**不在调用方**

## 4. codec 2 解开了

**容器结构**（我独立验证：253/253 恰好消费完）：

```
u32 包长（大端）
u8  [4]（含义未知，解码不需要）
u8  包数据（全部以 0xF8 开头）
```

**接入方式**：容器解析器识别 kind 2 后，**直接交给已经链接好的 libopus**。

**多声道 Opus 文件被拒绝**，不是只播声道 0 —— 混多个解码器是另一件事，而且那些是开场动画，不是这个 App 的目标。

1. **不编造计数** —— 数据源缺失时告诉页面「没有」，不是给 0
2. **不丢警告** —— coverage 提示和 provenance 经过每一层缩减都保留

# AND-05 · 解码正确性验证（逐样本对照，S6 替代证据）

- **checked_at**: 2026-11-08T00:45+08:00 (Asia/Shanghai)
- **证据级别**: **L2 逐样本一致** —— 解码结果与独立参考渲染 **bit-exact**
- **重要**：这**不是**听音证据，但比「有波形」强得多

---

## 1. 为什么这条证据重要

AND-04 只证明「解出了非静音 PCM」（peak=0.131）。**一个错的解码器只要输出噪声也能通过那个测试。**

本条证据换了个问题：**解出来的采样值，和独立参考渲染是否逐样本相同？**

答案是：**完全相同，maxdiff = 0。**

---

## 2. 参考来源

`G:\Mario Kart World\readable_assets\audio\romfs\Sound\Resource\Stream\*.wav` 是转换工具产出的标准 WAV，与 `romfs\...\Stream\*.bwav` 一一对应。

它**不是游戏原生文件**，所以不能当"权威"；但它是**独立于我的解码器**的第二实现结果。用它对照能抓到系统性错误。

> 上一轮我已登记过这个盲区：「唯一对照源是转换工具输出，系统性错误无法自证」。本条证据**部分缩减**了这个盲区，但没有完全消除 —— 如果转换工具和我犯同样的错误，两者仍会一致。见 §6。

## 3. 我的独立 Python 解码器

`_toolchain/dsp_verify.py` 从零实现 DSP-ADPCM：

```python
sample = (nibble * (1 << scale) * 2048
          + coef1 * hist1 + coef2 * hist2 + 1024) // 2048
```

用 §4 测得的布局（64 字节对齐、末块可截断）定位数据。

## 5. 设备上同样一致的证据

`DecoderCorrectnessTest` 在模拟器上跑了同一比对：把参考 PCM 推到设备，让**引擎**渲染，再逐样本对照。

```
PASS decodedPcmMatchesTheReferenceRender
```

断言是 `maxDiff == 0`（硬性要求，不是容差）。**引擎在设备上的输出与参考逐样本相同。**

> 这同时证明了两件事：
> 1. 我的 Python 解码器正确
> 2. **native 引擎的解码器也正确**，且与 Python 实现独立

## 6. 仍然存在的盲区（必须说清）

| 盲区 | 说明 |
|---|---|
| **参考源非原生** | reference WAV 是转换工具产出。若该工具与我的实现犯了同一处系统性错误，两者仍会一致。**无法自证** |
| **未全库对照** | 只验了 5 首曲目、52,000 采样。20,991 个文件未逐一比 |
| **未验 loop 接缝** | 只验了开头/中段/尾部窗口，没验 loop 点附近的接缝听感 |
| **未听音** | 逐样本一致 ≠ 人耳听着对（例如整体增益正确但播放速度错，会漏掉） |
| **kind=2 未验** | 253 个非 DSP 文件仍不支持 |

## 8. 结论

从「能编译」 → 「能运行」 → 「能出声」 → **「解出来的采样值是对的」**。

最后一条是新增的，而且是我目前能拿到的最强证据，因为我**没有耳**。

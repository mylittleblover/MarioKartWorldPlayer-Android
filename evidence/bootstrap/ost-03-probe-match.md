## 3. 匹配器设计要点（为什么这么做）

### 3.1 锚点用「目标资产名」

条目是过渡定义：`[源] [标签] [目标] [标签]`。源名 100% 解析不到 wav（那些是过渡的起点，不是文件），目标名 100%。

### 3.2 归一化只剥「已证实」的后缀

| 后缀 | 处理 | 依据 |
|---|---|---|
| `.yu.48` / `.tk.48` / `.nn.48` / `.mj.48` | 剥掉 | 数字部分 58/58 等于目标采样率/1000 |
| `.v02` | 剥掉 | 版本号形态 |
| `_2`（下划线数字） | **保留** | 真实资产名的一部分（`BGM_Stage_BigTree_Outro00_2`） |

### 3.3 重名一律 AMBIGUOUS，绝不自动选

已写成回归测试：两个不同路径同名文件 → `AMBIGUOUS`，`asset_path` 返回 `None`。

### 3.4 匹配器完全不碰文件系统

所有事实来自 `AudioProbe`。测试用一个**不存在**的路径验证：仍能匹配成功，证明匹配逻辑没有偷读磁盘。

### 3.5 名称匹配 ≠ 音频验证

代码和文档都明确：`EXACT_VERIFIABLE` 只表示"名字唯一对上"，**不表示** PCM 对、loop 对、录的是同一条音轨。

## 4. 停滞/拒绝路径

| 情况 | 行为 |
|---|---|
| 非音频文件 | `UnsupportedFormatError` |
| RIFF 头声明大小 > 实际文件 | `ProbeError` |
| 缺 `data` chunk | `ProbeError` |
| 不支持的 codec tag | `UnsupportedFormatError` |
| FLAC | `UnsupportedFormatError`（**明确不实现，不假装支持**） |
| BWAV 采样率离谱 | `ProbeError` |
| BWAV 声道数为 0 | `ProbeError` |
| BWAV 两处帧数不一致 | `ProbeError` |
| 同名多候选 | `AMBIGUOUS`，不给路径 |

## 5. 本轮明确未做 / NOT_RUN

| 项 | 状态 | 原因 |
|---|---|---|
| PCM 解码与帧校验 | **NOT_RUN** | VER-01 范畴 |

| `yu` / `tk` 语义 | **UNKNOWN** | 见 `suffix-semantics.md` |
| 任何 L3 行为验证 | **NOT_RUN** | 需游戏运行时证据 |
